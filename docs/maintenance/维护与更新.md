# V14.3 维护与更新

## rc.6：自动模式与原生能力边界

当前源码修订 `auto-local-family-r1`，六份 JS 默认请求 `auto`，每客户端仍一份入口，保留 `dual-stack`／`ipv4-local`。自动出口判断需要匹配原生核心，普通核心接受覆写不等于已接入；Shadowrocket 只保留原生 IPv4 偏好与 IPv6 开启。Windows 指定 FlClash 核心/Helper 已完成新编译和隔离验证，但本轮未安装，维护者此前手动兼容客户端不变。移动端受保护 socket 和其它平台宿主仍需独立接入，真实 TUN/媒体/公网 IPv6 未验收。当前说明与证据入口：`docs/guides/自动网络模式.md`、`docs/reports/v14.3/自动本地地址族与跨端能力.md`。

以下涉及 rc.5 的接入记录只认证原版本，不认证 rc.6 自动能力。


当前 `shared-runtime-r1 / single-entry-r1 / client-integration-r1`，入口由 `CURRENT_RELEASE.json` 指定。稳定合同在 `docs/需求.md`，动态验收在 `docs/status/当前验收.md`。历史文件和失败结论保持，不能用旧回执认证新源码。

## 修改与生成

生产运行函数在 `releases/v14.3/runtime/`，审核规则在 `data/`。构建器依次读取固定规则/有限审核输入、渲染共用函数、应用客户端适配和网络模式，输出六份 JS；Shadowrocket 是独立原生配置生成器。冻结 V14.2 输入用于数据/分类对照，不再作为文本锚点替换的生产业务源码。

每个客户端仅一个当前文件；JS 内含 dual-stack/ipv4-local 两模式，Clash Mi 返回对象并兼容 JSON 字符串输入。JS 保持 128 KiB 预算，标准合成配置 192 KiB，兼容合成配置 256 KiB。不要只修改 src 输出。

远程规则继续固定审核提交。更新前保存候选、SHA256、分类增删和 TCP/UDP/DNS 分组差异，审核后再更新锁；不得启用浮动来源或牺牲未知 UDP/STUN/节点失败保护。平台能力集中在 `data/client-capabilities.json`。

## 客户端和可选核心

先确认客户端/核心版本、网络接管方式和实际生效字段。`tools/diagnose-client.py` 只读输出允许字段和哈希；JSON 无外部依赖，YAML 需 PyYAML。FlClash/Clash Verge GUI 可能后置覆盖 DNS/TUN，应核对严格路由、核心 IPv6 和真实双栈路由，不能只看脚本标记。

本轮用户明确授权的维护者 Windows FlClash 已接入匹配核心/Helper。其它安装仍需要用户自己的相应授权。可选核心包仅适配明确原装 SHA256 的 FlClash 0.9.0，三文件成套替换、完整备份、失败回滚，保留 owner SID 与校验。核心和完整对应源码/锁定依赖单独分发，详见[核心指南](../guides/FlClash核心接入与回滚.md)。

有限 TUN、真实微信、其它平台设备、公网 IPv6 和跨网络重试分别验收。没有自动物理出口探测或任意 IPv6→IPv4 透明映射；应用失败也不得改出口 DIRECT。

## ipv6-fallback-r2（2026-10-16）

先生成标准 balanced/Mac/Shadowrocket，再运行 `node tools/build-network-compat.cjs`。五种 JS 的节点默认值在共同生成阶段注入；兼容入口由标准代码加独立适配生成，不能只手改输出。修改后运行新增静态和隔离核心，连同受影响的既有静态、完整/空表/冷下载与 Mac 核心回归。之后依次执行根 `restore-ios-delivery.py`、`record-macos.py`、`record-v14.3.py`，最后核对并打包。记录工具验证新增回执再写清单，不把旧概念实验改成当前源码通过。公开克隆从已记录的历史哈希保留历史引用，不要求取得私人归档。

需求第 12 条、模式指南、七个单入口、模式元数据和新回执均进入包；Mac 包包含两份可在文件内切换模式的 Mac 入口。审核包全新解压会重跑新增生成器和静态；隔离核心不会在包校验或 CI 中重新运行。真实 TUN、应用后备与跨网络切换须单独验收。参见 [模式说明](../guides/IPv4兼容模式.md)和[报告](../reports/v14.3/IPv6回退与兼容入口.md)。

rc.3 的 `native-network-compat.cjs` 会调用 `native-ipv4-recovery.cjs`；两者都须纳入哈希。新实验验证内部 DIRECT 解析、真实 IP DNS 例外、TLS/QUIC 域名恢复与 IPv4 节点承载 IPv6 TCP/UDP，保留生产规则并约束到回环。兼容 JSON 单列 256 KiB 预算，标准 JSON 的 192 KiB 和 JS 128 KiB 保持。rc.2 的宽泛拒绝不再作为方案；设备媒体结果仍待复测。
