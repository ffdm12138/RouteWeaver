## 生成与来源

从 releases/v14.3/ 运行 node tools/build-balanced.cjs。生成器验证不可变 V14.2 输入、公司/共享审核表、Azure/CDN 精确边界、官方 Clash Mi 桥快照及固定来源哈希，生成三个独立 JS。标准 Clash Mi 入口与带修订号入口必须同字节，返回对象。内嵌策略在 data/rules/embedded-policy.json；完整原始和有效分类器在 data/rules/reviewed/，客户端不读取这些本地文件。

JS 预算为 128 KiB，标准单合成节点配置预算为 192 KiB。母域须已有归属证据，不能把专属第三方子域升格为共享云母域。完整 CN 和长尾公司表保持远程，原生 Google/Microsoft 域名表用 MRS；OpenAI 原始表的第三方/宽 Azure 正则不启用，保留小型已审核完整表。

固定源见 data/rule-sources.lock.json。更新前先保存明确候选提交、原文件、SHA256、MRS 解码及增删，再审查 TCP/UDP/DNS 分组，尤其代理变 DIRECT、共享云错归属和关键词误匹配。高风险差异完成审核后再改锁、生成和复验，不改浮动分支运行地址。现有回归以冻结基线为准；实际允许的分类变动必须另有明确审核和相应断言。

python tools/review-remote-sources.py --download 只核对当前固定 URL，不修改来源锁。python tools/review-latest-candidates.py --core <mihomo.exe> 保存已捕获 HEAD 的候选和差异，不启用它们。当前 HEAD 身份见 validation/network-review/manifest.json；要调查之后的新 HEAD，应先保存新的完整提交证据。运行正常时核心按 86,400 秒维护 HTTP provider 缓存，脚本无网络请求或定时器。

## 复验

从 releases/v14.3/ 执行：

~~~text
node tools/build-balanced.cjs --check
node tools/build-macos.cjs --check
node tools/build-shadowrocket-lean.cjs --check
node tools/build-network-compat.cjs --check
node tests/static.cjs
node tests/macos-static.cjs
node tests/shadowrocket-lean.cjs
node tests/network-compat.cjs
node tests/native-network-compat.cjs <mihomo.exe>
node tests/native-core.cjs <mihomo.exe> <openssl.exe> --current-contract
node tests/native-macos.cjs <mihomo.exe> <openssl.exe>
node tests/native-boundaries.cjs <mihomo.exe> <openssl.exe>
node tests/native-boundaries.cjs <mihomo.exe> <openssl.exe> --cold-download
~~~

静态检查覆盖完整域名集合、关键域名无远程表、部分表失败、既有业务/UDP/IPv6 合同用例、三次幂等、从 V14.2 升级、对象返回、体积预算和上游反例。实际数量以绑定源码的 validation/static.json 为准。

本机核心使用自有回环节点、专用回环 DNS 和临时证书；生产 TUN 仅解析，执行关闭 TUN。只停止实验启动的子进程，不加载实际订阅，不改系统信任、不修改运行客户端。core 的完整表、有效空表、无缓存且下载被拒绝分别有回执。沙箱若拒绝 127.0.0.1，应保留失败后只为这个隔离实验申请权限，不能改成静态通过。设备接管和公开网络验收另记。

根目录执行：

~~~text
python tools/verify-v14.3.py
python tools/package-v14.3.py --node node
python tools/verify-v14.3.py --with-packages
~~~

公开 Git 克隆不包含本地根 `archive/`。在上述三个 Python 命令中追加 `--skip-history`，只跳过未公开旧档案核对，当前入口、需求、公开基线与核心回执哈希仍验证。公开 CI 与后续发版见[开源与发布](开源与发布.md)。

小火箭由 tools/build-shadowrocket-lean.cjs 从不可变基线生成自包含业务 DNS 与远程国内规则配置，--check 复验幂等。上述静态与必要核心回放完成后，在根目录执行 `python tools/restore-ios-delivery.py` 绑定当前 iOS 交付清单，再执行 `python tools/record-v14.3.py` 更新来源/核心回执和当前入口，最后验证与打包。上一 Clash Mi 调查的失败回执保留在修改前归档，不作为本轮通过证据。--current-contract 不执行旧的人为移除 API 例外反例；当前生产 A/AAAA 例外仍验证，旧失败不能改写。

修改 Mac 入口时，先运行 `node tools/build-macos.cjs`、Mac 静态与必要核心回放，再在项目根运行 `python tools/record-macos.py` 和 `python tools/record-v14.3.py`；后者保留两个 Mac 入口注册。生成器不改原平台 JS；仅修改 Mac 平台参数无需重跑哈希完全相同的原平台核心实验。新增 `dist/v14.3/v14.3-macos.zip`，审核包全新解压后也复验 Mac 生成与静态合同。

verify-layout.py 在当前版本为 14.3 时调用当前核对器。包校验检查 CRC、成员 SHA256、凭证范围和全新解压后的离线生成/静态合同；没有在包内重跑的原生实验不得称为 fresh native pass。包只带源码、公共规则与合成测试，核心二进制、缓存、私钥和实际订阅均不打包。

## 边界

远程下载失败时只保证经过本轮检查的关键内嵌名单；不能继续宣称 11 万条域名全量离线保留。其它未识别且不属于明确国内/局域网例外的目标保持代理或拒绝。节点失败不得自动改选或转 DIRECT。

iOS JavaScriptCore、最终应用合并、NetworkExtension、Android VPN、Shadowrocket 原生、公网出口 IPv6、浏览器和长时内存必须独立验收。本机 Windows Mihomo 不代表这些设备通过。Shadowrocket 原生完整国内 DNS 依赖直连 DNS/所选代理远端解析，有限 Host 模型不能认证原生跟随。详见[当前报告](../reports/v14.3/国内协议跟组与小火箭精简.md)。


## ipv6-fallback-r2（2026-10-16）

先生成标准 balanced/Mac/Shadowrocket，再运行 `node tools/build-network-compat.cjs`。五种 JS 的节点默认值在共同生成阶段注入；兼容入口由标准代码加独立适配生成，不能只手改输出。修改后运行新增静态和隔离核心，连同受影响的既有静态、完整/空表/冷下载与 Mac 核心回归。之后依次执行根 `restore-ios-delivery.py`、`record-macos.py`、`record-v14.3.py`，最后核对并打包。记录工具验证新增回执再写清单，不把旧概念实验改成当前源码通过。公开克隆从已记录的历史哈希保留历史引用，不要求取得私人归档。

需求第 12 条、模式指南、六份可选入口、模式元数据和新回执均进入包；Mac 包包含两份 Mac 兼容文件。审核包全新解压会重跑新增生成器和静态；隔离核心不会在包校验或 CI 中重新运行。真实 TUN、应用后备与跨网络切换须单独验收。参见 [模式说明](../guides/IPv4兼容模式.md)和[报告](../reports/v14.3/IPv6回退与兼容入口.md)。

rc.3 的 `native-network-compat.cjs` 会调用 `native-ipv4-recovery.cjs`；两者都须纳入哈希。新实验验证内部 DIRECT 解析、真实 IP DNS 例外、TLS/QUIC 域名恢复与 IPv4 节点承载 IPv6 TCP/UDP，保留生产规则并约束到回环。兼容 JSON 单列 256 KiB 预算，标准 JSON 的 192 KiB 和 JS 128 KiB 保持。rc.2 的宽泛拒绝不再作为方案；设备媒体结果仍待复测。
