# 开源维护与发布

公开仓库为 [ffdm12138/RouteWeaver](https://github.com/ffdm12138/RouteWeaver)，首个版本为 [v14.3.0-rc.1](https://github.com/ffdm12138/RouteWeaver/releases/tag/v14.3.0-rc.1)。当前标准及六个可选兼容入口和业务合同仍以根 `CURRENT_RELEASE.json`、[需求](../需求.md)为准。

## Git 约定

此目录是独立公开源，不引用外层个人工作区。共同设计合同保留十一条需求，个人目标地址及定制记录不随公开版分发。

默认分支 `main`，发布标签采用 `v<major>.<minor>.<patch>-rc.<n>`；全部设备验收完成前使用 GitHub Pre-release。标签一经公开不移动，后续修正增加版本。提交身份使用 GitHub noreply 邮箱，仅配置本仓库，不修改全局 Git。

`.gitattributes` 对现有文件禁用自动换行转换，保留 Windows / Linux 克隆中的 SHA256。不要批量格式化或归一化固定输入、需求、源码和回执。

`archive/`、`.work/`、`dist/`、实验目录、运行程序、证书私钥、真实节点/订阅和凭证排除在 Git 外；保留原文件于本地。当前验证所需的 `releases/v14.3/validation/inputs/` 会公开，包含原始基线、上游来源片段和已知失败反例。根 `tools/` 中部分旧工具被回执按哈希引用，不随意移动。

## 本地验证

公开克隆仅需 Git、Node.js 24.19.0、Python 3.12（CI 固定 3.12.10），无 npm / pip 依赖。从项目根执行：

~~~sh
python -m unittest discover -s tools/tests -p "test_*.py"
python tools/verify-v14.3.py --skip-history
python tools/package-v14.3.py --skip-history
python tools/verify-v14.3.py --skip-history --with-packages
python tools/audit-publication.py --strict --archive dist/v14.3/v14.3-deployable.zip --archive dist/v14.3/v14.3-audit-evidence.zip --archive dist/v14.3/v14.3-macos.zip
~~~

`--skip-history` 只跳过根 `archive/` 的历史核对，并记录 `SKIPPED_HISTORY`。它仍核对当前合同、生成器、入口、已公开固定基线和已有核心回执的实际哈希。已有核心回执的核对不等于重新执行核心实验；实机验收另行记录。

打包器使用固定 ZIP 成员时间、顺序与权限；相同输入在同一工具链下可重复产生相同 ZIP。每个包包含 `PACKAGE_MANIFEST.json`，逐成员记录 SHA256；旁置 `.sha256` 校验整个 ZIP。打包后全新解压审核包，重跑四组生成及 Windows/Android/iOS、Mac、小火箭静态检查。

| 产物 | 用途 |
|---|---|
| 六个标准及六个兼容 JS / conf 单文件 | 在对应客户端直接导入 |
| `v14.3-deployable.zip` | 全平台入口、使用文档、来源与许可 |
| `v14.3-macos.zip` | 两个标准及两个兼容 Mac 入口、文档、来源与许可 |
| `v14.3-audit-evidence.zip` | 当前源码、公开固定输入、测试和已有有界证据 |
| `package-verification.json` | 本次打包范围、哈希、全新解压回放结果和未验收项 |
| `SHA256SUMS.txt` | Release 全部附件的校验和，除校验和文件自身 |

首次公开前，逐项审阅暂存文件和发布包。扫描器读取 **Git 索引中的真实字节**，不会因工作区文件已被删去密码就漏掉已暂存的密码；也会拒绝被强行加入的本地档案路径。扫描只是一层启发式检查，来源和许可证仍需核实。

## 发版步骤

1. 检查 `git status`，把本轮更改加入暂存区；运行 `git diff --cached --check` 和严格扫描。
2. 在无根 `archive/`、`.work/`、`dist/` 的全新克隆运行上述验证，确认 `.github/workflows/verify.yml` 的 Windows 和 Linux 作业通过。
3. 更新 `CHANGELOG.md`、`PLANS.md`、`harness/build-log.md` 和版本说明，记录需求及六个入口的哈希、未运行范围。
4. 普通推送 `main`，创建指向验证提交的带说明标签。发布 Pre-release，上传十二个入口、三种 ZIP、包回执和校验和。
5. 独立读取远程分支/标签 SHA 和 Release 附件清单，重新下载附件逐字节核对 SHA256。完成情况写入构建日志。

首次发布本次已由用户明确请求；后续任务按各自授权范围执行。公开发布不会替换运行中的客户端。若远程出现已有提交，先检查分支关系；禁止强制推送或移动已公开标签。

## CI 范围

GitHub Actions 在 Ubuntu 和 Windows 上运行生成检查、来源和回执绑定、公开内容扫描、打包和解压静态回放；动作依赖固定完整提交 SHA，权限仅 `contents: read`，不保存 checkout 凭证。

CI 不下载浮动规则，不加载真实订阅，不接管系统 TUN/VPN，不认证 Android/iOS/macOS 实机。需要新核心实验时，按[维护与更新](维护与更新.md)使用隔离回环环境，结果单独绑定源码。


## rc.2 兼容修订

`v14.3.0-rc.2` 对应 `ipv6-fallback-r1`。发布前必须核对 `network-compat-delivery.json`、新增生成/静态、当前核心绑定和六份 `compatibilityEntries`；发布附件同时包含标准与兼容文件。继续预发布，未验收的设备接管与应用 IPv4 重试明确列出。已发布标签与附件不可移动覆盖；远程 CI 和所有附件下载 SHA256 实际结果补记在 Harness 执行记录。

## rc.3 兼容修正

`v14.3.0-rc.3` 对应 `ipv6-fallback-r2`。执行 46 项新静态、101 项隔离核心及受影响既有回归，绑定实际源码后生成三包；公开全新克隆、索引/包内容扫描和双平台 CI 分别验收。rc.2 标签/附件与历史记录保持。新版本撤掉宽泛 IPv6 拒绝，增加内部 DNS 过滤与 TLS/QUIC 域名重解析，Shadowrocket 明确只有偏好。用户 rc.2 媒体失败不能改写成通过；rc.3 持续作为预发布，应用复测另记。

## rc.4 HTTP 兼容补丁

`http-recovery-r1` 在既有 `ipv6-fallback-r2` 上补 HTTP 目标重解析，标准入口字节不变。51 项兼容静态、123 项隔离核心分别认证当前源码，标准核心按不变哈希核对。rc.3 标签/附件保持，新增 rc.4 Pre-release；新日志把 rc.3 媒体待测状态更新为实测失败，rc.4 仍未完成媒体实测。公开源码、全新克隆包、双平台 CI 和全部附件下载各自核验，不上传私人日志或个人包。
