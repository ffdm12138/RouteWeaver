# 自动网络模式（rc.6，auto-local-family-r1）

## 先确认核心能力，而不是只看脚本名称

每个客户端仍只有一份当前导入文件。六份 JS 默认请求 `auto`，同一文件保留 `dual-stack` 和 `ipv4-local`。**自动运行时判断需要实现 `auto-local-family-r1` 的匹配核心；普通核心接受配置、不报错，不能证明自动检测已经运行。**

本次提供的是 Windows FlClash 0.9.0 固定来源的可选匹配核心／Helper／manifest，以及完整对应源码。不是普通 Mihomo CLI，不能装到 Clash Verge、Clash Mi 或其它版本。Android、macOS、iOS 的原生集成和设备验收尚未完成；Shadowrocket conf 不能运行这项 Mihomo 扩展，保留 IPv6 与原生 IPv4 偏好并明示限制。不要把七个入口均已更新解读为七个客户端均已具备自动检测。

## 三段能力分别处理

本机到节点：未显式指定地址族的域名节点默认 `ipv4-prefer`，保留同一节点 IPv6 后备和用户显式设置。原始节点、provider payload 与刷新节点继承相同合同；字面量节点不会被凭空映射到另一地址族。TCP 地址竞争和 UDP 选址不是同一种完整重试机制。

节点到目标：不受本机出站传输地址族限制。以 IPv4 连接支持相应协议的节点，仍可以请求 IPv6 目标；节点自己没有对应出口则失败，不自动改节点或回落 DIRECT。

本机 DIRECT：匹配核心按实际所选出站接口读取源地址，结合近期原生 TCP 连接证据决定本地候选地址。不根据 TUN 地址、一个 AAAA 结果或默认路由就声称公网 IPv6 可用。网络监视器通知时失效旧证据，接口地址至少按一秒有效期重新观察。接口有 IPv6 源地址但尚无实际可达证据时保留双栈，不把猜测当作不可达。

## 自动模式实际改变什么

当实际出站接口缺少可用 IPv6 源地址，或短期存在多个独立前缀的原生网络不可达证据时，核心按连接或 DNS 请求调整候选；不关闭系统/核心 IPv6，不取消双栈 TUN 接管，不改分流或手动节点选择。

应用侧 AAAA／IPv6 Fake-IP 只有在**同名域名通过原内部 DNS 策略确认有 IPv4 A 替代**时才抑制；A 查询预算 250 ms，最多八路额外确认，查询失败、超时或无 A 时保留 IPv6。这样不会仅因本机没有 IPv6 就删除代理仍可能访问的纯 IPv6 域名。该确认是针对应用已经请求的同名域名，不是向公共探针额外发送检测流量，也不改 DNS 出口。

内部解析器、节点引导 DNS 与代理远端 IPv6 不被一刀切过滤。用户显式 hosts、局域网名称及私有/链路本地地址保留。可读 HTTP/TLS/QUIC 域名沿用原业务组重新解析；显式 IP 优先级与嗅探排除保留。直接目标有 IPv4 候选且没有显式 IPv6 偏好时，才根据本地能力去除不可用的 IPv6 候选；纯 IPv6 和字面量地址不被伪造转换。

正向可达证据有效 30 秒，多个不同 /48 的明确网络不可达负证据有效 5 秒；单个目标失败、超时、拒绝或取消不能永久禁用 IPv6。网络接口/代次及容量约束防止旧网络状态污染新网络。使用移动端受保护 socket 钩子时，当前实现明确返回未知并要求宿主提供真实出站能力，不根据 VPN 虚拟接口猜测。

## 导入与验证

导入并绑定当前客户端对应的唯一 JS，保持规则模式、核心 IPv6、TUN/VPN 接管和支持平台的严格路由。JS 的默认常量为 `auto`；要明确指定，也可在进入脚本的输入配置中设置：

```yaml
x-routeweaver:
  network-mode: auto
```

生成配置请求 `routeweaver-local-family: auto`。**该字段存在只是请求，不是能力证明。** 匹配核心的 `/configs` 读回应包含相同字段和 `routeweaver-local-state`（unknown/no-local-v6/local-v6-usable）。安全诊断工具必须同时核对这些原生运行时字段；仅有保存配置时会报告 `AUTO_NATIVE_RUNTIME_NOT_VERIFIED`。

```text
python tools/diagnose-client.py --config <最终配置路径> --expected-network-mode auto --live --strict
```

`--live` 只读取已经明确配置的 IPv4 回环控制器，不会替你开启控制器或输出密钥。没有控制器时可检查保存配置，但不能据此宣称原生自动能力通过。不要为了获取诊断结果开放公网控制端口。

普通核心尚未接入时，自动入口仅保留双栈、节点 IPv4 偏好及域名恢复等通用部分，不具备本修订的物理出口判断。需要保持已经验证的兼容效果时，使用同一入口显式 `ipv4-local`；真正可用的双栈网络可显式 `dual-stack`。当前维护者 Windows 的旧版手动兼容配置未被本次发版替换。

## 仍然不能承诺的情况

没有可靠域名或服务映射的普通 IPv6 字面量不能透明转换成等价 IPv4。保留 DIRECT 时必须存在真实可用的本地出口，或由应用自身选择 IPv4 后备。更快的连接关闭不保证应用启动 IPv4 竞争；不增加全局 IPv6 REJECT，不把 DIRECT 偷偷改代理，也不扩展未知 UDP 直连。

本次是带独立回执的预发布。源码、真实 JS 引擎、原生回环、实际 TUN、跨网络切换、真实微信媒体和其它平台设备必须分别验收；旧 rc.5 TUN 结果不认证新自动核心。详见[当前验收](../status/当前验收.md)与[本轮报告](../reports/v14.3/自动本地地址族与跨端能力.md)。

原生安装必须使用同一发布包的核心、Helper 和 manifest 成套安装，先校验支持版本／原装哈希并备份；完整对应源码和回滚工具随可选核心包提供。用户未执行安装时，不把“已下载／已导入 JS”当作核心安装完成。
