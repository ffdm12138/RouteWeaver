# 微信发图优化

适用于 V14.3 主版和纯 IPv4 版的七个入口。测试版的 14 个微信、媒体和头像域名后缀作为显式直连例外。切换「国内网站」的节点时，这些域名仍直连，其他国内业务按组选择。 [域名清单](../../releases/v14.3/data/rules/wechat-media.json)

| 客户端 | 微信媒体配置 |
| --- | --- |
| Windows FlClash、Clash Verge Rev | 媒体域名使用直连 DoH 返回真实 IPv4，并排除嗅探命中的媒体域名。核心识别到 `Weixin.exe` 或 `WeChat.exe` 时，只为无域名的 IPv4 连接补直连规则。 |
| macOS FlClash | 使用同一套媒体 DNS 和域名规则。无域名的 IPv4 连接按 `WeChat` 进程匹配。 |
| Android FlClash | 使用同一套媒体 DNS 和域名规则。无域名的 IPv4 连接按 `com.tencent.mm` 包名匹配，需要核心收到应用身份。 |
| macOS、iOS Clash Mi | 使用 Mihomo 媒体 DNS 和域名规则。 |
| iOS Shadowrocket | 使用原生 `always-real-ip`、`[Host]` 直连 DNS 和域名直连规则。地址族沿用各入口的设置。 |

Mihomo 主版在这批域名的 DNS 上抑制 AAAA、SVCB 和 HTTPS 记录。公司、局域网、外部 DNS 和通用 STUN 规则先于微信直连例外。应用送来的 IPv4 字面量只有在核心识别出对应进程后才会命中这条例外。 [Mihomo DNS 参数](https://wiki.metacubex.one/en/config/dns/#additional-parameters)

FlClash 可在合并时覆盖 `find-process-mode`。测试字面量连接时，检查最终配置使用 `strict` 或 `always`，并从连接页确认进程和命中规则。Mac 的 `tun.dns-mode` 沿用原配置，避免切换系统 DNS 注册方式后影响局域网和 MagicDNS。 [FlClash 配置合并](https://github.com/chen08209/FlClash/blob/v0.9.3/lib/common/task.dart#L179-L218) · [Mihomo 系统 DNS 问题记录](https://github.com/MetaCubeX/mihomo/issues/3420)
