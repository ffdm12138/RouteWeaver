# architecture-audit-r1：手动部署与验证

本轮只更新项目工作区和候选包。当前客户端未由审计程序切换配置、重启或更换核心。完整结果见 [全架构审计与修复](../reports/v14.3/全架构审计与修复.md)。

准确入口以 `CURRENT_RELEASE.json` 和 `releases/v14.3-ipv4-only/MANIFEST.json` 为准。候选 ZIP 保留原工作区相对路径。不要把 Windows 脚本当 Android 通用脚本，也不要把 FlClash 文件当作支持所有客户端的通用配置。

主版仍有 auto / dual-stack / ipv4-local；**auto 要求匹配的原生扩展**，普通官方核心仅加载成功不是自动探测通过。原本使用手动兼容模式的设备不要无意变回 auto。具体切换方法见 [IPv4 兼容模式](IPv4兼容模式.md) 和 [自动网络模式](自动网络模式.md)。本次未修改这些既有需求。

## 导入后看最终配置，不只看 JS

在方便中断当前连接时，由用户手动导入并确认订阅实际绑定新文件，保留原手选节点。然后导出客户端最终配置做只读检查：

```powershell
python tools/diagnose-client.py --config "你的最终配置.yaml" --expected-network-mode ipv4-only --strict
```

主版对应使用 `ipv4-local`、`dual-stack` 或 `auto`。JSON 输入不需额外依赖；YAML 需要 PyYAML。不要将配置原文发到公开 Issue，诊断输出已省略节点、账号、控制器密钥和原始规则。该工具默认不访问控制器；明确加 `--live` 时也仅允许已配置的 IPv4 回环端点，并禁止重定向。

### 纯 IPv4 特别注意

本轮只读检测发现一份现用配置虽然 marker 是 ipv4-only，顶层 `ipv6` 仍为 true。新生成脚本输出为 false，说明仅替换脚本未必能覆盖 App 后置合并。应检查客户端 IPv6 / 通用覆写开关以及最终配置，直到诊断不再报告 `PURE_IPV4_CORE_FLAG_OVERRIDDEN`。

DNS 的 `ipv6: false` 与顶层 `ipv6: false` 不是同一个字段。纯 IPv4 还要遵循原变体 README 的 App/系统 IPv6 接管要求；不应因发现此项不一致就关闭主版全部 IPv6。保留严格路由、DNS 策略和既有的未知 UDP 失败关闭保护。

### 安全告警

`LAN_PROXY_WITHOUT_AUTHENTICATION_REVIEW_INTENT` 表示已允许局域网访问且未看到代理鉴权。确需共享时应检查来源限制和防火墙；不需要共享时可由用户关闭，审计没有自动更改。

`NODE_TLS_VERIFICATION_DISABLED_REVIEW_SUBSCRIPTION` 表示部分节点包含跳过服务端证书校验。不要把此告警误说成已经泄露，也不要不核对证书就批量改动订阅；优先采用提供有效证书的节点配置。

`NON_LOOPBACK_CONTROLLER_WITHOUT_SECRET` 是更明确的控制面风险，应避免把无认证控制器暴露给非受信网络。

## 台湾节点的检测异常

不要以 Net.Coffee 一项“Cloudflare IP 获取失败”决定整套脚本好坏。隔离测试已在不使用覆写、嗅探和 TUN 时复现 `1.1.1.1:443` TLS EOF，同时普通 Cloudflare / ChatGPT trace 可返回 200。

本轮没有为该目标改分流。给节点服务商反馈时，只需要提供“同一节点访问 IP 字面量失败、域名成功、TLS 提前关闭、时间和节点名”等最小信息；不要附带订阅密钥或完整 HAR。

## 复验与发布

```powershell
python tools/verify-current-audit.py
node tools/test-architecture.cjs
python -m unittest discover -s tools/tests -p "test_*.py"
```

验收清单一旦封签，重跑写回执会改变证据文件哈希；这是预期的失效保护。开发时完成重跑、重新审查后，再运行 `tools/record-current-audit.py` 建立新的当前清单并打包，而不是手工改哈希绕过失败。旧 `verify-v14.3.py` 用于旧证据链，不能代替本轮当前清单。

未验证设备先按有限候选试用，不建议把“源码通过”当作全员无条件升级依据。没有执行真实账号任务、支付、订阅管理或公网 API 赠金消费。
