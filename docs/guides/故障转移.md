# 策略组故障转移

当前候选用于 Windows amd64 FlClash 0.9.3。个人版、公开版均覆盖主版和纯 IPv4 版。配对核心读取 `routeweaver-failover` 并生成「故障转移1」「故障转移2」「故障转移3」。若现有覆写已在合并配置中写入该字段，直接沿用。 [0.9.3 配对、部署与重建说明](../../releases/v14.3/research/proxy-failover/FlClash-0.9.3.md)

## 怎么选

- 业务组继续选原来的节点 A。三个备用组均默认 REJECT。在哪一档选了节点，就启用哪一档。
- A 确认故障后，按 **1 → 2 → 3** 选择可用备用。优先级较高的出口恢复后，新连接自动切回。A 恢复优先切回 A。
- 单档选 REJECT 跳过该档，三档均选 REJECT 则立即交回原策略。A 与所有启用备用均不可用时，新连接只尝试 A。A 被订阅移除且没有可用备用时拒绝连接。
- 「漏网之鱼」和选代理的「国内网站」也参与。主动 DIRECT 或 REJECT 以及明示直连和拦截规则照常执行。「自动选择」独立运行。
- 连接日志记录原策略和生效节点。新建 TCP、UDP 和业务 DNS 上游连接按同一出口决策。选定出口不支持 UDP 时拒绝该 UDP 流量。应用重连后才会重新选择已有连接的出口。

当前手选节点按实例去重，每 5 秒做一次 HTTPS 204 探测，超时 3 秒。两次连续失败后判定故障，故障后连续两次成功才判定恢复。A 初始先试，备用至少有一次新鲜的成功结果才可接管。

## 其他客户端

其他 Clash 客户端须由匹配核心通过同一受控出口合同后启用。Shadowrocket 的开发者版本记录确认有原生 fallback。三档共用、跳档和关闭、恢复切回及 FINAL 与业务组的 TCP、UDP、DNS 实际出口仍需 iOS 真机逐项验证。 [Shadowrocket 官方版本记录](https://apps.apple.com/us/app/shadowrocket/id932747118)
