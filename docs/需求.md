1. **按公司分组**：OpenAI、Anthropic、Google、Microsoft 等各自归组，不串组、不泄露；Gemini、YouTube 统一属于 Google。共享基础设施独立归组，不随意归属某家公司。

3. **UDP 跟随策略组**：包括 QUIC、语音、WebRTC 等；能识别的业务 UDP 跟对应公司组走，节点不支持 UDP 则拒绝，不得偷偷直连。
4. **IPv4/IPv6 双栈正常**：直连和代理连接在相应出口具备能力时均支持双栈，按第 12 条区分本机、节点和目标的地址族；所有应代理流量不得绕过代理，尤其防止 IPv6、DNS 和 UDP 泄漏。
5. **保留 DIRECT 选项**：各业务组允许用户主动选择 DIRECT，包括相应 DNS/UDP；但代理故障、节点失效或协议不支持时不得自动回落直连。

7. **统一兜底**：未知 TCP、UDP、DNS 统一归入「漏网之鱼」，只允许代理，不得非预期直连；明确授权的国内和局域网直连除外。
8. **规则优先级**：已知业务优先归对应公司；通用 STUN 防漏先于宽泛国内直连，不能抢占已识别业务。
9. **规则更新安全**：远程更新不得未经审核改变重要分流，尤其代理变 DIRECT、业务错分组和 DNS/UDP 出口不一致；高风险更新需审核后启用。
10. **三端一致性与验收**：Windows FlClash/Clash Verge Rev、Android Mihomo/FlClash、iOS Clash Mi/Shadowrocket、macOS FlClash/Clash Mi 尽量保持相同组和语义；验证 TCP、UDP、DNS、IPv4/IPv6、节点故障及切换。TUN/VPN 模式重点防泄漏，系统代理模式明确接管边界。
11. **国内网站集中切换**（用户 2026-10-10 追加，2026-10-13 明确修订）：保留「国内网站」手动组，默认 DIRECT，可跟随「高纯净度AI用」「高网速视频用」、选单节点或主动 DIRECT。当前已审核国内域名主表、22 项补充、关键母域和已声明的 `.cn` 后缀，其普通 TCP、UDP、DNS 统一跟随此组；不再把这些域名的全部 UDP 当作未知流量送去兜底。公司/共享业务、局域网及显式手动例外先行；能识别的通用 STUN/STUNS 主机与标准端口在普通国内域名规则之前保护。仅凭 CN IPv4/IPv6 地域命中的无域名流量仍只放行 TCP；未知公网 IP 的 UDP、未知域名 DNS和可识别的通用 STUN/WebRTC 继续经「漏网之鱼」代理或拒绝。`.cn` 已在审核表和本地合同中明示，属于域名例外；不得把这个例外扩大为所有 CN IP 的 UDP 直连。覆盖以已审核规则为限，不宣称穷尽国内网站或识别隐藏在普通 HTTPS 名称/端口的 STUN。业务及国内组选代理时，代理失效或不支持 UDP 均拒绝，不得回落 DIRECT。DNS 按域名选择，无法按尚未发生的连接端口区分同名普通业务与隐藏 STUN；这个既有上下文边界必须单独说明。Shadowrocket 的原生 DNS 与代理端远端解析仍须实机验收。

12. **本地缺少 IPv6 出口时的兼容**：区分本机到节点、节点到目标、本机直连目标三段能力。保留核心 IPv6、双栈 TUN 接管和代理远端 IPv6；原出口有相应能力时双栈正常。不得因本机缺少 IPv6 就全局关闭 IPv6、静默换节点、把 DIRECT 转代理或把代理失败转 DIRECT。具体行为见下文。

总体原则：按公司归组，按手动策略组选择出口；已审核国内域名 TCP/UDP/DNS 跟随国内组，CN IP 地域捷径仅供 TCP。保留成熟功能，整理代码时不减少任何保护。

## 本地 IPv6 与网络模式

- 本机到节点：未明确指定地址族的域名节点默认 `ipv4-prefer`，保留同一节点的 IPv6 后备。原始节点、provider payload 和刷新后的节点均覆盖；保留用户显式地址族和 provider 表达式。字面量节点不能凭空得到另一个地址族，不因不可达擅自换节点。
- 节点到目标：与本机到节点独立。本机用 IPv4 连接支持相应协议的节点，仍可访问 IPv6 目标；TCP/UDP 分别验证，节点没有 IPv6 出口时保留失败，不绕回 DIRECT。
- 本机直连目标：需要真实可用的出口。TUN/ULA 地址、默认路由或 AAAA 响应都不能单独证明公网 IPv6 可用。可靠的受控 IPv6 隧道可以作为出口，不能一概排除。

每个客户端在 `src` 中只有一份当前导入文件。用户 2026-10-16 明确追加：六份 Mihomo JS 默认请求 `auto`，同一文件保留 `dual-stack` 与 `ipv4-local`，不依靠全局禁用 IPv6 解决。自动模式需要真实原生核心/宿主能力，不得把静态脚本标记、生成或解析通过称为自动检测成功；当前实现与设备验收分别列出。模式切换不改变公司、国内、兜底和节点组的出口语义。Shadowrocket 保留一份原生双栈配置及 IPv4 偏好，其配置不能实现本 Mihomo 扩展，必须明确未实现边界。

IPv4 兼容模式过滤应用 AAAA，并对业务/直连上游过滤 AAAA、SVCB、HTTPS，移除 IPv6 Fake-IP 池；核心 IPv6 与双栈 TUN 路由保持。业务 DNS 出口保持原策略组，节点引导 DNS、LAN/system 和用户显式 hosts 保留独立语义。该模式会影响 IPv6 地址与服务发现/ECH 提示，需要明示其适用网络。

HTTP/TLS/QUIC 中可可靠读到域名时，在原业务组下重解析目标；保持既有端口范围、用户嗅探排除、局域网名称及明确 IP 优先级。不得根据共享 CDN IP、PTR、历史嗅探域名或截取 IPv6 地址猜测等价 IPv4。无域名/可靠映射且应用没有 IPv4 后备时，维持 DIRECT 仍需真实 IPv6 出口；不能承诺透明转换任意 IPv6。

原生 DIRECT TCP 在无 Host 覆盖的 IPv6 字面量上收到系统网络不可达时，应及时结束同一次连接的无效重复拨号，保留原错误，新连接和网络恢复后重新尝试。IPv4、IPv4 映射、有 Host 的解析、代理传输、超时、其它错误和 UDP 不套用此条件。嗅探只在现有字节已不可能属于所识别协议时提前放弃；合法分片、公司域名识别、原时间预算和内存上限保留。

静态 JS 不持续探测物理出口。自动能力状态应由客户端/核心依据有效路由和有时限的实际可达性证据维护，网络切换使旧状态失效。不能仅因某个目标失败永久禁用 IPv6；不增加宽泛 IPv6 REJECT、全关嗅探或扩展 CN UDP 直连来掩盖缺口。

## 严格路由、客户端合并与验收

支持严格路由的 TUN 客户端必须开启严格路由；App 管理的设置要在 App 中开启，并核对最终生效配置。JS 写入值不代表 App 后置合并仍保留该值。业务 DNS 由本覆写管理时，额外 DNS 覆盖不得破坏跟组与过滤要求；系统代理模式单独说明较窄的接管范围。

Windows FlClash、Clash Verge Rev、Android Mihomo/FlClash、iOS Clash Mi/Shadowrocket、macOS FlClash/Clash Mi 分别记录能力和验收。Node、QuickJS、Boa、核心回环、原生 TUN、应用体感和其它平台设备不能相互替代。真实引擎对照需覆盖对象返回、异常输入、provider、命名/依赖、幂等及网络模式；Clash Mi 的对象桥和 JavaScriptCore 仍需各自验收。

新增网络验收覆盖：本地 IPv4-only/可用双栈，同一节点一种地址族不可达、AAAA-only/字面量节点、IPv4 传输承载 IPv6 目标、远端无 IPv6、provider 刷新、显式设置、TCP/UDP/DNS、无域名/缓存地址及 Wi-Fi/热点/TUN/VPN 重连。失败反馈与应用实际选择 IPv4 分开记录；微信图片发送时间属于应用观察，不能用受控 socket 耗时冒充。

规则来源固定审核提交；共用函数、平台适配、网络模式和生成校验分阶段维护。正式导入文件自包含，不依赖本地仓库或运行时 npm。个人版与公开版共用生成源码和相同功能合同；明确个人目的地址规则单独维护，不随开源版发布。

## 自动本地地址族实现的附加验收合同（2026-10-16）

自动判断按实际出站接口、网络代次与有时限的源地址/原生 TCP 证据进行；未知状态保留双栈，不通过公共 canary 额外暴露用户网络活动。单目标失败、超时、拒绝、取消和 UDP socket 创建不认证 IPv6 不可用/可用。受保护 socket 的宿主必须提供真实出站能力，不能从 VPN/TUN 虚拟地址推断。

应用侧 AAAA/Fake-IP 的自适应抑制必须先经原 DNS 策略确认同名 IPv4 A 替代；确认有时限和并发上限，没有 A、错误或超时不得删除仍可能通过代理访问的 IPv6-only 域名。内部 DNS、节点引导 DNS、代理远端 IPv6、用户显式 hosts 和地址族保持独立。可读域名的重解析不能成为根据共享 IP、PTR 或历史名称猜测等价目标的借口。

每个入口同时声明原生扩展需求与未接入边界。配置-only 诊断不得给出运行时自动能力通过；须核对真正运行核心的扩展状态。发布入口、原生核心构建、对应源码、真实 TUN、网络切换与应用媒体分层验收；没有对应客户端改造时，不宣称所有平台已实现全自动。
