## 路由变化与微信排查

此前已审核国内域名 TCP 经过「国内网站」，但全局公网 UDP 兜底规则先于国内域名，普通国内 UDP 会经「漏网之鱼」；其常规 DNS 也优先使用兜底出口。国内网站默认 DIRECT 并不能让这两类请求同步直连。这是配置层面可复现的问题，但用户未提供手机连接日志、实际上传目标或同图同 Wi-Fi 开关 VPN 对照，不能断定微信图片上传使用了这些 UDP 请求。

现在国内域名规则位于一般公网 UDP 保护之前，DNS 按相同已审核域名表跟组，包括统一补充、关键母域和已经明确声明的 .cn 域名后缀。公司、共享云、手动规则和 LAN 保持优先。标准 STUN 端口与可识别 stun/turn 名称在国内域名前仍受保护；未知公网 IP-only UDP 仍代理或拒绝。CN IP 地域捷径继续仅影响 TCP。普通国内 HTTPS 名称/端口隐藏的 STUN 无法仅靠这些规则识别，DNS 查询本身也不携带未来连接端口，不能宣称内容层穷尽防漏。

szfile.weixin.qq.com、szextshort.weixin.qq.com、wxapp.tc.qq.com、qlogo.cn、mmbiz.qpic.cn 增加 TCP/UDP、国内组主动直连/代理及无 UDP 节点拒绝用例。它们代表审核域名覆盖，不能当作用户当前上传端点的实测记录。共享云 ASN 或腾讯全网段未为微信整体放行；带 IP-ASN 的外部微信列表仅保存为候选，没有替换固定来源。

[Clash Mi #535](https://github.com/KaringX/clashmi/issues/535) 是 iOS Wi-Fi IPv6 QUIC 0 B 的用户记录，虽然国内策略显示 DIRECT，仍有加载超时；[Mihomo #3075](https://github.com/MetaCubeX/mihomo/discussions/3075) 记录其他平台微信 IPv6 TCP 重传。这些是排查 IPv6/TUN/实际 MTU 的线索，平台和版本不等同于本用户，不能作为已确认根因。没有获得能确认此次为微信服务端故障的权威证据。安卓把应用排除在 VPN 外、桌面未走相同 TUN 时，也不能替代 iOS 路由对照。

移除 111,464 行重复的完整 CN 内嵌域名表，完整国内分流由原先已审核的固定 CN RULE-SET 加载；关键母域、必要原生兼容规则和完整业务 DNS 表保留。Google 原始正则、Microsoft 泛关键词等候选未未经审核移植。配置体积减少约 71.7%，保留 DNS 表意味着不会缩成几 KB。用户无需提供额外公开托管地址。

业务与关键国内 Host DNS 显式使用业务组/国内组。完整国内长尾 DNS 采用已有原生 direct-dns-server、always-ip-address=false 和所选节点远端解析语义；这些语义来自[公开配置作者的手册](https://github.com/LOWERTOP/Shadowrocket/wiki)，原生代码未开放，本机不能验证。必须实机核实 .conf 原生编译、Host 优先级、proxy=组名、DNS 切换复用、远程节点解析和 VPN 接管。静态模型没有把完整国内 DNS 当作原生通过。直接 DNS 失败是否符合最终严格拒绝合同也须原生检查。

先保留节点订阅，再导入 src/ios/v14.3-shadowrocket.conf，全局路由选择「配置」，两个公共组手动选可用节点。原生配置的 RULE-SET 刷新/缓存由小火箭管理，首次下载需检查规则加载状态；不把 Mihomo 的 24 小时间隔认证为小火箭的刷新行为。

## 本轮验证及边界

三份 JS 每个平台对 233,396 个有限域名样本检查正常 TCP 路由与 DNS，917 个业务/UDP/显式 DIRECT 例子，以及 1,058 个关键域名的空表 DNS 和 4,232 次空表路由组合；27 项静态检查通过，重复生成和多次覆写幂等通过。正常 TCP 的有限样本分组与旧审核基线一致，DNS 仅按新授权的国内合同改变。

隔离 Mihomo v1.19.31 实际加载生成配置，执行关闭 TUN，使用自有回环节点与 DNS。完整表三平台路由 2,751 次、DNS/Fake-IP 1,293 次、选择器 336 次、入站保护 6 次；有效空表和首次无缓存且下载被拒绝，每种状态各有 282 次路由、294 次 A/AAAA DNS。所选代理失效的国内 DNS 不查询直连上游；未知 UDP 和不支持 UDP 的代理不自动直连。回执均绑定实际源码和测试哈希。

当前核心回放使用 --current-contract，只执行当前生产配置；此前人为移除 API real-IP 例外的旧 Fake-IP AAAA 反例失败证据仍保留，没有改为通过。当前真实地址 A/AAAA 例外仍执行。IPv6 回环预检被本环境 EACCES 拒绝，DNS AAAA 查询结果可测试，IPv6 传输/节点拨号不能因此称为通过；公网 IPv6、设备 VPN 和浏览器也未验收。

小火箭检查覆盖 232,528 个有限域名的 TCP/普通 UDP 分组、9,129 个原业务 DNS 样本、关键微信 DNS/冷缓存规则、未知 IP/STUN/公司优先级/无 UDP 拒绝模型。5 项有限源码模型检查通过，原生解析与网络行为为 NOT_RUN。

部署包及审核包重新生成后执行 CRC、逐成员 SHA、全新目录两个生成器 --check 和两套静态模型。打包回执不声称重新执行原生核心；已包含的核心回执通过源码哈希绑定。包不含真实订阅、节点密码、控制器凭证、私钥或核心二进制。当前入口、交付清单、来源清单与测试状态见 CURRENT_RELEASE.json、metadata/balanced-review.json、metadata/ios-delivery.json 和 validation/ 各回执。

未替换运行客户端，未访问用户手机。配置层面的国内 UDP/DNS 不一致已按授权修正，微信发图速度仍待用户设备实测。
