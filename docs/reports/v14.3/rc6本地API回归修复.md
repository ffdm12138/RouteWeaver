# rc.6 本地 API 回归修复

日期：2026-10-17。修订：`controller-readiness-r1`，基于公开 `v14.3.0-rc.6` 的本地维护候选，尚未发布新标签。

## 问题与可确认的原因

rc.6 发布时，`native-core` 在读取 `/proxies/…` 时超时，`balanced-empty-core` 在等待 `/providers/rules` 时连接被拒绝。二者都是隔离核心回放失败，不能据此宣称业务路由算法失败或所有客户端的自动模式已验收。

本轮先保存原始 FAIL 回执、运行日志和相关旧测试，再用同一个 SHA256 的回放核心执行未修改的测试：完整与空表回放均通过。因此原始故障的精确触发条件未被重现，不能把根因确定为纯测试误报。原始失败与修改前通过记录分别保存在 `releases/v14.3/validation/history/rc6-api-regressions/`。

代码中可以确认的薄弱点是：旧就绪检查按次数等待，单次连接/响应没有统一的实际时间上限；普通请求只重试连接重置与断管，不处理短暂的连接拒绝或超时；部分清理路径会在进程已经退出后才等待 `exit` 事件。新测试记录确实观察到控制器启动期间短暂的 `ECONNREFUSED`，随后约百毫秒内就绪，但这不证明它就是原始两条失败的唯一原因。

## 改动与失败边界

共享回放控制器位于 `releases/v14.3/tests/native-controller.cjs`。它给每个隔离核心分配独立的 HTTP 连接池；单次请求采用 1.5 秒实际时间上限，覆盖连接、排队和读取响应；就绪检查总预算 10 秒，仍要求真实 provider 计数符合原条件。

仅幂等的 GET/PUT/DELETE 可对连接拒绝、重置、断管或超时进行最多两次重试；它不重启核心，也不重放非幂等 POST。持续错误、核心退出、HTTP 拒绝、无效 JSON 和 provider 条件不满足都必须失败。退出监听先于清理注册，已退出进程立即返回，存活进程的停止也有期限。

完整、空表、冷下载、Mac 和 Clash Verge 的聚合回放携带同一控制器源码，并将其 SHA256 写入回执。所有原有分流、DNS、UDP、防直连回落及节点选择断言保留。七个导入入口、共用运行时和固定规则来源没有修改；没有安装核心或更改运行客户端。

## 独立验证

| 检查 | 次数和观察 | 当前结果 |
|---|---|---|
| 控制器反例 | 8 项：迟启动、静默超时、重置后恢复、持续重置、POST 不重放、HTTP/JSON 错误、空 provider、核心提前退出 | PASS |
| 完整核心回放 | 两次，每次 4,386 项：路由 2,751，DNS 1,293，选择器 336，入站 6 | PASS |
| 空表核心回放 | 两次，每次 576 项：路由 282，DNS 294 | PASS |
| 冷下载失败闭合 | 一次，576 项 | PASS |
| 两种 Mac 入口 | 一次，2,924 项 | PASS（Windows 回环） |
| Clash Verge 入口 | 一次，1,462 项 | PASS（Windows 回环） |
| Python 维护工具 | 31 项，含回放控制器入口及证据篡改反例 | PASS |

`releases/v14.3/validation/native-api-repair.json` 汇总最终回放的实际退出码、时间、逐次回执、日志、源码及历史证据哈希。`known-release-regressions.json` 将原始 FAIL 与当前通过回执分开，验证工具同时核对两者；不能通过修改状态字符串替代复跑。

本轮修复后的七次原生回放合计 14,886 项观察。修改前基线和控制器反例不计入该数字。

路由阶段合计完成 249,797 次本地控制请求。18 次核心启动记录到 36 次暂时连接拒绝，均发生在 provider 就绪检查阶段，92～166 ms 内恢复；业务检查期间未记录传输重试。这是本次实验结果，不是永久消除间歇故障的保证。

## 发布与设备状态

rc.6 标签自身缺少 `native-tests.log` 的 CI 失败保持历史事实；该文件已由 `e342ed4` 纳入 Git，[后续四项 CI](https://github.com/ffdm12138/RouteWeaver/actions/runs/38949814062) 全部成功。本地维护候选必须另记当前检查结果，不能借用这次旧 CI 认证新代码，也不覆盖已公开标签或附件。

上述结果限于 Windows 上的自有回环核心和本地工具，不认证 Android/iOS/Mac 原生接管、Windows 自动核心实际 TUN、真实微信媒体、网络切换、公网 IPv6 或长期运行。自动模式仍需要匹配的核心与宿主支持。
