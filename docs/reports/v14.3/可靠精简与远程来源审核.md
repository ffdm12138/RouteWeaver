# V14.3 可靠精简与远程来源审核

日期：2026-10-12。修订：`balanced-r1`。用户已确认原大脚本会卡住或闪退，临时精简版可运行；本轮将精简做成有固定来源、边界和复验的版本。未导入真实订阅或替换任何运行客户端。

## 体积与内嵌边界

| 入口 | V14.2 原大小 | V14.3 大小 | 降幅 |
|---|---:|---:|---:|
| Windows | 2,036,611 B | 114,695 B | 94.37% |
| Android | 2,036,477 B | 114,581 B | 94.37% |
| Clash Mi | 2,036,035 B | 117,466 B | 94.23% |

原体积主要来自 111,595 条国内后缀。完整国内表、Apple/Meta 等长尾及 Google/Microsoft 完整业务表改由远程来源承担；国内、Google、Microsoft 和 IP 集合使用原生 MRS，较小且需保留正则的分类继续使用已审核的 classical 表。

内嵌保留 199 个业务母域、164 个业务精确端点、经过审核的专有/共享核心边界，以及小型安全表。精确端点没有升格为公共云母域。局域网表 131 条、应用 DoH 安全表 127 条、国内重要母域 51 条保留；原有 22 项国内边界补充仍在。Clash Mi/Android 生成配置有 665 条 inline provider 成员，Windows 因应用 DNS 规则表示不同为 792 条；这些计数含安全和核心表，不等于独立站点数量。

单个合成节点的 Clash Mi 返回配置约 170 KB，真实订阅大小另计。生成器对 JS 设置 128 KiB 上限、标准合成配置设置 192 KiB 上限，避免无意把全量表再次塞回脚本。脚本独立运行，无文件读取、网络请求或 JS 定时器；下载和缓存由核心处理。

## 远程来源审核

原来的 45 份运行来源、7 份公司候选，共 52 份固定文件已重新下载，SHA256 全部与此前审核快照一致；另下载并解码固定的 Google/Microsoft 域名 MRS 两份。当前原生来源锁收录 30 份，标准 Windows 实际使用 30 份，Android/Clash Mi 使用 29 份，后两者不另建立 category-doh HTTP provider。每份运行 URL 都固定完整 Git 提交，每 86,400 秒由核心更新，不追踪浮动分支。

固定 MetaCubeX 提交为 `b4d414227a182c5bc954283e4a83ee176dad671b`。又保存了最新 HEAD `83c8208bdfae92b1caaa29745f51f233b6f1847e` 的全部 30 份原生候选；有效域名/IP 集合没有增删，保留当前固定提交。原始字节、MRS 解码和候选差异均有回执。Shadowrocket 本轮未更新，其 V14.2 blackmatrix7/MetaCubeX 固定来源和验收边界保留。

本轮没有把上游分类名称当作公司归属证明。试接原始公司表时发现并保留了两项反例：

- OpenAI 表包含 `crixet.com` 等未确认的第三方，以及超出已批准 eastus 1/17/23 精确主机的 Azure 正则。原版已审核层没有将这些目标归 OpenAI；新版本同样不接入这个原始 provider，完整已批准的 OpenAI 小表直接内嵌。
- 微软 classical 表的 `DOMAIN-KEYWORD,1drv` 会命中国内的 `51drv.com`，另有 onedrive/skydrive 宽关键词。改用域名 MRS，保留已有微软精确租户地址；`51drv.com` 的 TCP 仍归国内网站，DNS 仍归原兜底策略。

Google/Gemini/YouTube 同组、公司先于地域、共享云独立、业务 DNS 同组、未知公网 UDP 代理或拒绝、节点失效不切 DIRECT 均由本项目规则层实施。共享命名空间前仍有已审核精确租户例外。普通规则集示例中的 `MATCH,DIRECT` 或宽泛云品牌归组不直接采用。

## 主流规则集如何选择

不存在可核验的统一“口碑最好”排行。以下是官方仓库在本轮查看时的近似关注规模及用途，Star 数不是正确率。

| 项目 | 近似 Star | 适用性 |
|---|---:|---|
| [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) | 5.3k | Mihomo 原生 MRS 与分应用集合，当前原生客户端继续优先采用 |
| [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script) | 28.2k | 细分服务和多客户端格式，也构成 MetaCubeX 国内表的上游之一；保留 Shadowrocket 来源用途 |
| [Loyalsoldier/clash-rules](https://github.com/Loyalsoldier/clash-rules) | 28.8k | 每日构建的通用直连/代理名单；单独使用不足以实现本项目逐公司 DNS/UDP 出口合同 |
| [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) | 9.7k | 社区 geosite 上游，需经过格式构建与审核再用于当前客户端 |
| [ACL4SSR/ACL4SSR](https://github.com/ACL4SSR/ACL4SSR) | 6.8k | 常用 Clash 规则片段和配置生态，最终策略及共享云归属仍需本项目审核 |

结论是保留 MetaCubeX 的原生交付格式和成熟上游，叠加自己的小型关键域名与归属审核层。换一个更高 Star 的整包不会自动满足当前合同，也不需要叠加多套重复的全量名单。格式和上游关系可见 [MetaCubeX 说明](https://github.com/MetaCubeX/meta-rules-dat/blob/master/README.md)；每日构建及通用名单用途见 [Loyalsoldier 说明](https://github.com/Loyalsoldier/clash-rules/blob/master/README.md)。

## 验证与实际限制

源码回归：每个平台在完整远程表下对 233,396 个有限域名/子域比较 TCP 分组和 DNS 分组，无差异；每个平台 882 项既有业务、UDP、IPv6 和主动 DIRECT 用例通过。远程域名表全空时，1,058 个关键名称执行 4,232 次 TCP/UDP/协议支持状态比较和 1,058 次 DNS 比较，通过。正常、三次幂等、V14.2 升级、实际对象返回、体积预算、候选哈希和两项上游反例复验均通过。

本机 Mihomo v1.19.31：三个真实 JS 输出分别通过 882 次路由、409 次 DNS/Fake-IP、112 次手动选择器观察、2 次入站观察；合计 2,646/1,227/336/6。入站负例是实验内注入固定 DIRECT 的受控配置，不代表当前版本曾部署过该配置。路由试验使用专用回环 DNS；DNS 实验使用回环 DoH/DoT 与测试证书。

有效空表与首次冷下载被拒绝分别通过三个平台的 282 次路由、294 次 A/AAAA DNS 观察。冷下载实验实际删除全部域名缓存、拒绝回环 HTTP 下载，并确认各域名 provider 的 ruleCount 为零；IP 表仍用审核缓存。关键名称继续归组，故障节点不改选、不切 DIRECT。首次 DNS-disabled 测试曾触发宿主系统解析器，已保留失败记录并用受控回环 DNS 修正测试环境；OpenSSL 缺失默认配置的环境错误也有记录，临时配置仅作用于测试进程。已通过且源码相同的路由阶段复用原回执，其余阶段补跑，记录明确区分。

完整长尾分流需要成功加载远程表或有有效缓存。精简后不再承诺 11 万条域名在完全无缓存时与完整表相同；关键内嵌服务有基线，其他未识别且不属于明确国内/局域网例外的目标保持代理或拒绝。所有已批准国内/局域网例外和业务主动 DIRECT 仍存在。

源码、本机回环核心、包完整性分别报告。以上不是 iOS JavaScriptCore、Android VpnService、Shadowrocket 原生、Clash Mi NetworkExtension、公网出口 IPv6、浏览器/WebRTC 或长期内存验收。新版 Clash Mi 手机导入与长时使用为 `NOT_RUN`，需要用户重新导入本版复测。

当前证据目录为 `releases/v14.3/validation/`，来源与源码绑定在 `metadata/balanced-sources.json`、`metadata/balanced-review.json`。原版文件及失败反例保留原始字节；旧报告没有改写成新版本结论。
