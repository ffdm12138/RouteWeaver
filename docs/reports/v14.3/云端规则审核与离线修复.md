# 云端规则审核与离线修复

修订 `domestic-resilience-r1`，2026-11-07。范围为个人版、公开版，各自两条网络版本的七客户端入口，共 28 份文件。附件是对照证据，附件中的校园网和强制直连代码不是本轮需求。

## 确认问题与修复

| 问题 | 修复前证据 | 修复 |
|---|---|---|
| 远程规则为空时，部分抖音、微信流量及 DNS 落入漏网之鱼 | 每个发行口味 55,224 项模型检查中 23,040 项失败；`validation/domestic-resilience/before.json` 绑定原入口和测试哈希 | 共用离线数据补齐固定抖音表的 71 个后缀、6 个微信必要后缀及 11 个精确辅助主机；原有 qq/qpic/gtimg 等审核保护保留 |
| OpenAI 基金会官网漏收 | 每个发行口味 504 项公司覆盖检查中 28 项失败；`validation/cloud-rule-audit/before.json` | 第一方 `https://openai.com/foundation/` 跳转确认 `openaifoundation.org`，按公司后缀规则补入 TCP/UDP/DNS |
| API DoH 精确策略被前面的公司 DoT 策略遮住 | Windows 隔离核心实际观察 `api.openai.com` 走 DoT；个人版 `native-attempt-05.json` 及其合成输入、日志保留；公开版旧提交模型 `dns-order-before.json` 为 12 项失败，修复后同一测试 36 项全通过 | 精确 DoH 策略移至首个规则集之前的同一字面量段；增加按 Mihomo 有序策略段建模的反例及真实 DoH 出口检查 |

第三项与第一项是不同缺陷。Mihomo 把连续字面量 DNS 策略组成域名树，遇到规则集时结束该段；后续精确条目不能越过先前已匹配的策略段。此前模型把全部字面量放在规则集前，掩盖了此问题。封签 `tests/fixture.cjs` 保持原字节，新模型及原生回放承担这项验证。

API 修复适用于保留真实 API 解析例外的主版 auto/dual-stack。ipv4-local 和纯 IPv4 版继续沿用既有 Fake-IP 与地址族过滤合同，不把它们写成同一 DoH 例外。DNS 查询和连接均保持用户选择的公司组，没有增加直连后备。

## 云端审核结论

当前运行来源继续固定提交。审核核对 30 个 Mihomo 来源及 15 个 Shadowrocket 来源的文件和分类器 SHA-256，并保存四个新上游候选，固定到 MetaCubeX 提交 `7226545410c4dbb3854a5235803a26d86a298072`。清单、差异和决策在 `validation/cloud-rule-audit/review.json`，可运行 `node tools/audit-cloud-rules.cjs` 复核。

| 集合 | 审核结论 | 处理 |
|---|---|---|
| 抖音 | 上游与当前固定表均为 71 条，内容相同 | 继续固定引用；关键表另内化，解决下载失败时的覆盖缺口 |
| 国内 CN 总表 | 新候选新增 76 条、删除 1,494 条；不能由地域名称推断所有公司归属 | 保留旧审核提交；不整表升级，不扩大共享 CDN 和未知公网 UDP 直连 |
| OpenAI | 新上游 25 条，仍含未经公司归属确认的第三方和过宽 Azure 表达式；本地已保护已审核业务和专用租户 | 保持审核过的本地公司表，不恢复原始整表；补已确认基金会官网 |
| Anthropic | 当前 9 条核心及主要官方服务已有本地保护；新上游 19 条，其中 10 条新候选未取得充分第一方归属证据 | 保留固定引用和现有内嵌核心；新增候选逐条列入差异，不凭相似名字吸收 |
| 共享依赖 | 登录、验证码、支付、遥测等不能因被 ChatGPT 使用就视为 OpenAI 所有 | WorkOS、Intercom、SendGrid、Cloudflare、Stripe、Sentry、Datadog 保持公共基础服务；Apple 主机保持苹果组 |

“已覆盖”指本次官方资料和已审核清单的有限范围，不表示穷尽所有现用域名。未来新增域名仍需证据、固定字节与分流差异审核。公司表完整性、云端下载可用性、缓存恢复和客户端执行超时分别判定。

## 老补丁取舍和兼容边界

老脚本中的抖音小表作为固定来源核对；微信强制 DIRECT、独立直连 DNS 和校园网域名定制不迁入通用版。微信、抖音普通 TCP/UDP/DNS 跟随“国内网站”，默认 DIRECT，但可跟随公共组或选单节点。公司、共享业务、通用 STUN、未知 IPv4/IPv6 UDP 仍先保护。共享 CDN 只添加有证据的精确主机。

六 JS 继续对象返回、自包含及 128 KiB 预算。内嵌数据使用紧凑 JSON，避免把增加规则直接转化成同等脚本体积增长。Shadowrocket 保留完整业务 DNS 和 1.8 MB 预算；删除被更早同组后缀无条件覆盖的规则，并使新增 STUN DNS 覆盖使用一个同组加密解析器。普通业务 DNS 继续保留原有解析器。Shadowrocket 原生通配、组跟随和 iOS VPN 行为未实机验收。

三档回退仍为 A → 1 → 2 → 3，活动链 3 秒探测、3 秒超时。两个公共组保留手选入口，内部使用隐藏原生链；不能把旧文的“没有 fallback 入口”误读成不执行当前三档回退。provider 订阅沿用原分流并提示；已有连接需重连后重新选路。

不全关 IPv6、Fake-IP 或嗅探来掩盖媒体故障。网络模式、客户端配置归属和原生 auto 能力保持原合同。没有修改运行中的客户端、系统代理、TUN、Helper 或服务。

## 验证和限制

新回执位于 `releases/v14.3/validation/domestic-resilience/` 及 `validation/cloud-rule-audit/`，绑定实际入口、数据、模型和测试哈希。失败的构建/模型/原生探针保留，后续通过不覆盖这些失败记录。旧 native-fallback-r3 与 architecture-audit-r1 回执只认证各自旧字节。

回归包含完整、空、部分缺失、恢复四种规则模型；主版三种模式、纯 IPv4、两种发行口味；抖音视频/图片/API、微信媒体、公司和共享依赖；DIRECT/公共组/单节点与 UDP 不支持反例。Windows 核心回放使用唯一 IPC 管道、临时目录、合成 SOCKS/HTTP/UDP/加密 DNS；关闭 TUN，按同策略组替换回环解析器，不能证明公网解析器、手机 App 或 NetworkExtension 可用。

真实 QuickJS 与 Node 对照使用既有 18 类输入（包括异常、重名、provider、依赖、对象返回与幂等），另观察 1/50/500/2,000 节点规模。桌面耗时不构成 iOS 超时已修复的证据。CI 另运行 Windows/Linux 与真实 QuickJS/Boa 合同。

附件日志中的三次脚本超时、其它 853/代理连接失败和微信偶发卡顿，没有被本轮全部还原。它们不能并为同一个原因；iOS/Android/macOS 真机媒体、完整 TUN/VPN、Shadowrocket 原生 DNS、原生 auto 恢复和真实 AI 账号任务继续标记 **NOT_RUN**。
