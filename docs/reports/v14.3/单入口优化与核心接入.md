# 单入口优化与核心接入

2026-10-16，修订 `shared-runtime-r1 / single-entry-r1 / client-integration-r1`，交付 `v14.3.0-rc.5`。保留严格路由、核心 IPv6、双栈 TUN、公司优先、原 DNS 跟组和 UDP/STUN 防护。个人版和公开版共用实现；个人例外通过独立数据输入，公开版移除该输入。

## 单入口与共用源码

`src/` 现在只有七个当前文件：六份 JS 和一份 Shadowrocket 原生配置。删除重复的 `-ipv4-local` 文件和冗余 iOS 别名；旧文件保存在本地归档/既有 Git 标签中。每份 JS 包含两种模式，默认 `dual-stack`；使用 `x-routeweaver.network-mode` 或顶部 `ROUTEWEAVER_DEFAULT_NETWORK_MODE` 选择 `ipv4-local`。Shadowrocket 保留 IPv6 与 IPv4 偏好，能力不等同于 Mihomo。

先从原有源码抽取共用函数，初始迁移个人/公开共 26 个物理文件逐字节一致，再整理单入口。生产生成器依次加载审核数据、渲染共用函数、应用客户端适配和网络模式；不再从冻结 V14.2 JS 反复替换业务代码。冻结规则、失败证据和历史输入保持原字节。客户端导入文件自包含，不需要仓库路径、npm 或网络执行代码。

Clash Mi 原有的对象返回和 JSON 字符串输入都保留。真实 QuickJS 0.12、Boa 0.22 与 Node 对照覆盖六份 JS、两种模式、18 类输入，共 432 项；这证明语言/输出兼容，不能代替 App 导入、JavaScriptCore 或 VPN 验收。

## 两处核心等待

基于现用 FlClash 0.9.0 的固定源码与实际 Mihomo 分支构建，保持原宿主接口。不是将标准 Mihomo CLI 直接替换到 FlClash。

1. 只对原策略已经选择 DIRECT、无域名、原生 IPv6 TCP 目标、非内部 DNS，并且操作系统明确返回网络不可达的拨号，保留原错误并停止同一失败路径的十次退避。没有全局失败缓存、自动改出口或 IPv6 拒绝规则；IPv4、代理节点、超时、UDP 不改。
2. TLS 已收到的首字节/版本主字节已经不可能是合法 TLS 握手时立即拒绝该协议候选。合法短前缀、跨记录 ClientHello、延迟分片及原有内存和时间预算保留；HTTP/QUIC 不改。

原装/候选 FlClash 核心经官方 IPC 对照，文档 IPv6 不可达目标的三次拨号警告由每次 10 条变为 1 条，反馈中位数约 3437 ms → 16 ms。候选核心和匹配 Helper 已实际接入维护者 Windows FlClash，保留 Helper 的核心哈希校验、服务 owner SID 和应用 manifest，不绕过校验。

| 同一 IPv6 目标的原生 Windows TUN 探测 | 原装 | 候选 |
|---|---:|---:|
| 8000，无首包 | 2500 ms | 15 ms |
| 443，首字节明确不是 TLS | 4656 ms | 31 ms |
| 443，完全无首包 | 3734 ms | 1000 ms |

这些是有限受控失败反馈，不是图片上传吞吐率或微信发送耗时。Helper 日志只捕获 stderr，本次未得到对应网络警告计数；实际重试数证据来自隔离 IPC。原装 Go 1.27.1，候选 Go 1.27.2，版本/构建和二进制哈希单独保存。

现用单入口沿用 `ipv4-local`，最终应用配置检查保留 rule、IPv6、TUN、strict-route 和 HTTP/TLS/QUIC 目标恢复；26 个业务组、483 个 DNS 策略、960 个过滤上游均保持。FlClash 可能将生成的 route-address 覆盖为空，因此实际 IPv6 TUN 默认路由另外按 Windows 路由表检查。重载前后最终配置字节相同，说明整理没有改变原分流；实际导入文件哈希另行记录。

## Clash Verge 与诊断

新增 Windows Clash Verge Rev 入口。固定审阅 2.5.8、提交 `4337bd85758d54d7b9044b2da3c9ac1176eae1f3`，使用真实 Boa 0.22 对照。该 App 会在脚本之后恢复 GUI 拥有的字段，所以必须按[使用说明](../../guides/ClashVerge使用说明.md)保留规则模式、IPv6、严格路由，并避免应用 DNS 页面覆盖脚本解析策略。未安装或替换 Clash Verge 自带核心，FlClash 专用二进制不能用于 Verge。

`tools/diagnose-client.py` 只读输出最终配置的允许字段、计数、哈希和差异，省略节点名、URL、密码、目标和原规则；可选读取已配置的回环控制器。JSON 无外部依赖，YAML 需 PyYAML。能力表统一在 `data/client-capabilities.json`。

## 发布与边界

当前回执分别绑定静态、真实引擎、隔离核心、有限 Windows TUN 和包复验。隔离回放专用启动器只补 FlClash 宿主通常负责的入站启动，禁止启动 TUN；不会用于生产安装。回放中的配置重载必须等实际 provider 成员就绪，不能将未装载完成的选择器当作业务失败。

可选 Windows 核心包仅针对来源和原装 SHA256 均匹配的 FlClash 0.9.0，包含核心、按同一哈希构建的 Helper、manifest、备份与回滚脚本。独立对应源码包包含固定源码、补丁、锁定的 Go/Rust 依赖和原许可，构建工具不安装或修改运行客户端。核心派生部分遵守 GPL，根 MIT 许可不替代上游条款。详见[核心接入与回滚](../../guides/FlClash核心接入与回滚.md)。

用户观察的约 5 秒是主观基线，用户选择正常使用后反馈，本轮没有发送微信消息/图片，也不要求人工对照。完全没有域名信息的任意 IPv6 字面量仍不能可靠推导 IPv4；本次让不可达快速反馈，应用是否重试由应用决定。无首包仍保留识别等待，不能承诺所有连接数百毫秒完成。没有自动物理网络探测、透明 IPv6→IPv4 转换、其它平台原生设备或公网 IPv6 验收。

最新范围见[当前验收](../../status/当前验收.md)，稳定业务合同见[需求](../../需求.md)。rc.1～rc.4 标签/附件及历史失败结论不改写。
