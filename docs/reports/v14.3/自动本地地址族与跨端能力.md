# 自动本地地址族与跨端能力

修订：`auto-local-family-r1`，预发布 `v14.3.0-rc.6`。任务开始于 2026-10-16；最终构建、云端提交与发布时间以发布回执为准。所有运行中客户端在本轮保持原状态，维护者 Windows 仍使用此前已生效的手动兼容模式。

## 需求与交付边界

用户要求一个客户端一份入口，网络有 IPv6 时正常使用，缺少本地 IPv6 出口时避免错误候选造成等待，同时保留本机到节点与节点到目标两段独立地址族。不得靠全关 IPv6、偷偷改出口、切节点或扩展未知 UDP 直连实现。

六份 JS 已由共同编译器生成默认 `auto`，同一入口仍支持 `dual-stack` 与 `ipv4-local`。它们共享业务规则、DNS 跟组、节点 IPv4 偏好和通用域名恢复。**静态覆写本身不能持续检测网卡；自动检测由本次新增的原生核心扩展实现。** 仅修改脚本无法使未接入扩展的客户端自动具备该能力。

| 客户端 | 当前源码/配置交付 | 原生自动能力与设备状态 |
|---|---|---|
| Windows FlClash 0.9.0 指定来源 | 单入口，独立匹配核心、Helper、manifest、完整对应源码 | 新核心编译、单测、回环验证；本轮未替换现用客户端，TUN/媒体仍待验收 |
| Windows Clash Verge | 同一业务合同与自动能力请求 | 不提供可直接替换的 Verge 核心；不能安装 FlClash 二进制冒充接入 |
| Android FlClash/Mihomo | 同一业务合同与自动能力请求 | VPN 受保护 socket 的真实出站能力需宿主接入；本轮未装设备 |
| iOS Clash Mi | 对象返回兼容、同一业务合同与自动能力请求 | 需其 App 核心/宿主接入，JavaScriptCore/NetworkExtension 未验收 |
| macOS FlClash/Clash Mi | 两份各自客户端单入口、相同业务合同 | 未交付已验收 Mac 核心或设备接入 |
| iOS Shadowrocket | 原生 conf、IPv6 开启与 IPv4 偏好，增加能力限制说明 | 不能通过 conf 运行本 Mihomo 扩展；自动检测未实现于该客户端 |

因此本轮不能命名为“所有客户端自动回退已解决”。发版包含实现、可复验的能力请求及显式平台限制；不将 JSON 成功生成或原生配置解析成功计作设备自动能力。

## 原生实现

新代码在 `research/auto-local-family/core-auto.patch`，叠加于保留原字节的 rc.5 固定核心来源与补丁。完整对应源码包包含原模块、vendor 中对应实现、固定依赖及许可证，不用一个补丁代替完整源码分发。

核心观察真实选定的本地出站接口，源地址缓存有效期一秒；默认接口变更通知立即失效旧记录。状态区分未知、没有本地 IPv6、近期 IPv6 可达，不能把虚拟 TUN/ULA 地址或一个默认路由直接叫公网 IPv6 可用。有源地址但尚无实际证据时保留双栈。

近期真正的本地 IPv6 TCP 成功形成 30 秒正证据；两个不同 /48 的原生 ENETUNREACH 可形成 5 秒负证据。超时、拒绝、取消、字符串相似错误、同一前缀重复失败和 UDP socket 创建不构成该证据。所有证据按接口/网络代次和有界容量隔离。已有受保护 socket 钩子的宿主路径明确返回未知，不越权绕过宿主保护。

DNS 仅在应用响应端调整：无本地 IPv6 时，确认同名域名在原内部 DNS 策略下存在真实 A 替代，才抑制公网 AAAA 或 IPv6 Fake-IP；确认预算 250 ms、最多八路，未知或无 A 保留 IPv6。因此代理可达的纯 IPv6 域名不会仅因本地无 IPv6 被删除。内部解析器与节点引导 DNS 保持独立。用户 hosts、局域网名称、私有/链路本地/loopback 及另一路可用出口保留；修改 AAAA 结果时不保留失真的 DNSSEC AD 与对应签名声明。

本地拨号只在有 IPv4 候选且无显式地址族/IPv6 偏好时去掉已知不可用的 IPv6 候选。远端自定义 dialer 不套用本地判断；节点选择、代理内的远端 IPv6 地址不变。DIRECT UDP 的隐式偏好与 TCP 竞争各自实现，不宣称 UDP 业务重试已经有协议确认。

HTTP/TLS/QUIC 可读取域名时沿原策略组重解析。无域名缓存或私有协议下发的普通 IPv6 字面量不会被猜测成 IPv4；此前快速失败补丁保留，但它不等于应用一定重试 IPv4。

## 公开版 rc.6 已知未通过回归（仅限预发布）

本节记录已发布 rc.6 的历史失败。当前本地维护候选的控制器修复、原始证据保留与独立复跑结果见[rc.6 本地 API 回归修复](rc6本地API回归修复.md)，尚未发布新标签。

2026-10-17 的独立公开工作树原生回放中，native-core 的本地 /proxies API 超时，balanced-empty-core 的 /providers/rules 就绪检查出现 ECONNREFUSED。真实非零退出码及回执 SHA256 记录在 releases/v14.3/validation/known-release-regressions.json。未证实这两项是协议缺陷还是实验资源／就绪时序，不能把它们当作通过。同一轮独立的 auto-native 33 项和多项业务、DNS、兼容检查通过。另一份私人定制源码的整体复跑通过不抵消公开版的失败。用户明确接受携带上述风险的 rc.6 预发布，正式稳定发布前仍应处理。未装自动核心的客户端、原生跨端网络切换、真实媒体、公网 IPv6 仍待验收。

## 验证体系与实际证据

`validation/auto-local-core.json` 记录当前核心、匹配 Helper、原生补丁和 Go 测试日志哈希；`validation/auto-local-native.json` 记录实际编译核心的回环 DNS/SOCKS 测试，均以最终文件中的状态和数量为准。

新增测试分别覆盖接口源地址、状态过期、不同网络代次、两个独立错误前缀、显式家族、受代理控制的远端拨号、正向证据和 UDP 误判、DNSSEC 数据不变性、同名 IPv4 确认、纯 IPv6/错误/截止期与并发饱和。原有 DIRECT 快速失败和排除条件一并复验。早期编译/RPC 超时记录留在私人实验目录，不作为通过证据。

原生回环实验逐个解析六个实际自动入口；用自己控制的 DNS 服务器验证 A/AAAA、Fake-IP、显式 hosts、真实 IPv6-only 与 Fake-IP IPv6-only 域名，验证应用侧过滤与内部 AAAA 保持独立，以及通过 IPv4 SOCKS 节点传递完整 IPv6 远端目的地址。auto/off/auto 是受控配置对照，不冒充真实无线网络切换或公网 IPv6 可用性实验。

既有全量域名分类、国内 TCP/UDP/DNS、未知 UDP/STUN、显式直连、空表/下载失败、Mac/Verge、兼容模式及真实 QuickJS/Boa 对照按各自输入哈希重新验证。静态旧配置对照把本轮刻意改变的嗅探设置独立出来，与已验证兼容嗅探逐字段比较；规则、节点、DNS 上游和策略组仍要求严格不变，不移除失败断言掩盖分流差异。

安全诊断不再把“auto 标记存在”认证为自动能力。只有实际原生读回包含 `routeweaver-local-family` 与有效的 `routeweaver-local-state` 才可确认扩展在运行；仅保存配置、旧核心或移动端未接入宿主分别报出未验证/未实现边界。

## 发布、更新与回滚

本轮更改项目内共享源码、所有七个当前入口、模式/能力元数据、诊断及测试、需求与使用文档，公开版和个人版保留同一功能合同。个人目的地址例外继续由独立输入控制，不复制到公开仓库。

可选自动核心使用新名称，与 rc.5 已发布二进制、原始来源、历史 TUN 与离线重建回执分开保存。不能用 rc.5 Helper 配新核心；新包检查内嵌核心 SHA、manifest、三文件匹配、原安装版本与回滚备份。新包本轮未安装到任何运行客户端，原工作中的手动兼容模式不动。

发布前执行公开目录秘密检查、生成/测试绑定、包 CRC/SHA 与解压复验；云端提交、CI 与附件校验以发布回执为准。旧标签和 Release 附件保持不可变。客户端自身更新可能替换定制核心，重新导入也可能改变所选模式；必须重做能力读回，不能凭版本名称猜测。

未完成的独立验收包括：自动核心的 Windows 实际 TUN/微信媒体、真实网络切换、公网 IPv6 端到端、长时运行、其它平台原生宿主接入。上述限制会随入口说明和发布说明一同交付。

官方语义依据：https://wiki.metacubex.one/en/config/dns/ 、https://wiki.metacubex.one/en/config/proxies/ 、https://wiki.metacubex.one/en/config/sniff/ 。读取到的官方字段语义与本项目新增扩展须区分，`routeweaver-local-family` 不是声称上游已有的通用字段。
