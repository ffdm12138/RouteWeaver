# V14.2 三端雷霆独立审核与修复 R2

**日期：2026-10-10。状态：源码与隔离本机 Mihomo 核心通过，Shadowrocket 原生及实际设备接管未验收。** 修订：`thunder-repair-r2`，在 `thunder-repair-r1` 上继续；不是新主版本，也没有替换用户正在运行的配置。

当前合同以 `docs/需求.md` 的十一条为准，未更改需求原文。源码哈希、修复前文件及输入哈希分别记录于 `releases/v14.2/metadata/thunder-r2-review.json` 和 `releases/v14.2/validation/inputs/thunder-r2-before/manifest.json`。完整 R1 工作区（含原交付包）只读保存在 `archive/v14.2-before-thunder-repair-r2-20261010/`，不得把历史 R1 回执改称为 R2 测试。

## 1. 审核方法与判定范围

逐端分析 Windows FlClash/Mihomo、Android Mihomo 覆写、iOS Shadowrocket 生成配置及生成器；通过已锁定 45 个远程来源的原始字节/分类器哈希核对规则；构造旧版可复现反例；跨端比对域名路由、DNS 出口、UDP、已知共享云、国内 DIRECT 与未知代理兜底；真实 Mihomo v1.19.31 在本机回环测试 TCP、UDP、A/AAAA、选择器、失效节点，禁止加载真实订阅或启用 TUN。

判定为四层：**源码静态检查、真实 Mihomo 核心、ZIP 独立复验、实际客户端/设备接管**。前一层通过不能替代后一层。没有实机 Shadowrocket、手机 VpnService 或 Windows TUN 网卡外抓包，不能称三端零泄漏已验收。

## 2. 新发现与精确修复

| 编号/严重度 | 修复前反例 | 本次处理 | 结果 |
|---|---|---|---|
| **R2-01 / MAJOR** | Windows 继承旧 `GEOSITE,openai` 子规则时，固定提交映射缺项竟回退到浮动 `meta` 分支；“审核后更新”被绕过 | 来源识别与创建分开；缺少经审核的完整提交、仓库与文件路径精确匹配时拒绝生成，不写成移动分支 | 两个 JS 的来源缺项、伪提交、错误仓库/文件注入均拒绝，原字节来源未变 |
| **R2-02 / MAJOR** | iOS 原生混合 `RULE-SET` 中的泛关键词（如 `netflixdnstest`、`nicegram`、`twitter`）、`USER-AGENT`、`IP-ASN` 及广域 IP 可能抢走其他公司/兜底流量，TCP 分类与 Host DNS 不一致 | 用已审核 MetaCubeX 分类器重建 Netflix、Disney、Epic Games 的限定 DOMAIN/DOMAIN-SUFFIX；IP 使用同一份已审核 Mihomo CIDR 快照，保留 `no-resolve`。剔除缺乏等价安全表达的泛关键词、UA、ASN 等；不将整个云宿主归公司 | 六个嵌入式来源投影，规则和 DNS 有限域名样本不再错配；**iOS 原生仍未验收** |
| **R2-03 / MAJOR** | HTTP 订阅 `proxy-providers` 未填写 `proxy` 或指向旧版已删除组，原来静默改成 `DIRECT`，可能直接访问订阅服务端 | 改为 `REJECT`，给出告警；保持用户**显式**选择 `DIRECT` 或明确可用节点的能力，旧选择仍可无损继续 | 两个平台的冷启动、旧组引用、重复覆写及显式 DIRECT 反例均通过；首次订阅获取需配置引导出口 |
| **R2-04 / MAJOR** | Android/iOS 的 `dns.alidns.com`、`doh.pub`、`dns.pub` 等确切 DoH 端点仍可能落入默认国内 DIRECT，与 Windows 原有阻断不同 | 基于已固定 `category-doh` 快照，仅补十个精确 DoH 域名（另有 `dns.cloudflare.com`、`one.one.one.one`、`dns.cfiec.net`、`sm2.doh.pub`、`doh.360.cn`、`doh-pure.onedns.net`、`doh.onedns.net`）；公司及通用 DNS 策略不做宽泛更改 | 三端新增 TCP/UDP 静态及两套 Mihomo 真实核心拒绝测试通过；不是任意自定义 DoH 的通用封锁 |

投影的原生列表不再含会触发跨公司归组的非有界 Netflix/Telegram/Twitter 关键词。Netflix 在 Mihomo 分类器中的 4 条 DOMAIN-REGEX、Disney 的 1 条 DOMAIN-REGEX、Epic Games 的 3 条 DOMAIN-REGEX 未被不安全地近似为宽泛后缀；这些未确认动态端点走**受保护的代理兜底**，可能导致特定服务未归专属组，而非扩张错误归组。Shadowrocket 对 DNS Host、通配符和 HTTP 连接的真实解释仍需原生执行验证。

在 10,325 域名集合中，仍观察 **136 个跨端分类差异**（包括历史 DoH、LAN、平台原生源差异）。这说明三端总体行为**没有完全等价**；新修复没有用有限样本的“零 DNS 错配”掩盖这些差异。独立回执保存在 `releases/v14.2/validation/`，其中 `thunder-r2.json`、`thunder-domain-coverage.json`、`native-routing.json`、`native-dns-egress.json`、`native-selectors.json` 均绑定具体当前文件 SHA-256。

本轮核心拒绝场景有两次不稳定的首次失败：一次等待 `unknown-no-udp-crixet.com` 的拒绝日志时超时，一次读到 TCP `ECONNRESET`。各自重跑后均完成整套通过。后续改进了**测试程序本身**：REJECT 的硬判据改为无转发连接、无转发数据包，日志是否出现 REJECT 只作观察；本机控制器仅对幂等 GET/PUT/DELETE 的瞬时 ECONNRESET/EPIPE 有界重试，其他错误仍失败。改进后连续两轮完整 TCP/UDP 核心回归通过。**还没有证明首次抖动的唯一原因**；不把测试程序修好等同于生产核心漏洞已修复。

## 5. 仍须解决的问题（不得写成 PASS）

**P1：实机边界。** Windows 多网卡 TUN、IPv6 网卡外流量；Android 开机 VPN/IPv6 及“不允许绕过”；iOS Shadowrocket [Host] 的 `#proxy=`、策略组断节点、缓存、DNS 重用、QUIC/IPv6 UDP 拒绝；应用使用自带 DoH/DoT、VPN 外请求或 ECH 时可能无法归属，需以实际双栈 DNS/UDP 抓包判断。没有抓包无法承诺“零泄漏”。

**P1：原生覆盖差异。** 一些无法安全转换的正则、原生 IP-ASN 或 USER-AGENT 规则已收窄，会改变 Netflix/Disney 等特定场景的命中率；相较错误归组，当前选择安全兜底。若要恢复覆盖，须收集实际主机样本、验证租户归属后才新增有界规则，禁止凭关键词扩大整片云基础设施。

**P2：订阅引导易用性。** 旧提供者没有 `proxy` 字段时现在会被显式拒绝下载；用户可在原始配置中指定一个现成可用的**具体代理节点**，或在确认允许直连订阅服务时明确设置 `proxy: DIRECT`。这与业务组的主动 DIRECT 不同。不能在冷启动阶段引用尚未下载完成的同一 provider，否则可能形成依赖闭环。

**P2：测试中的拒绝日志抖动。** 已不再用单个关键字作为通过的唯一判据，并为控制器加有限重试。仍建议追加不同 Mihomo 核心版本、不同 Windows 网络环境的长时间压力测试，进一步区分主动拒绝、连接关闭和日志异步输出；目前只验证了连续两轮完整通过。

## 6. 使用与复验

从项目根目录执行（`<mihomo.exe>` 指经过 SHA-256 核验的本机核心）：

```powershell
node releases/v14.2/tests/static.cjs
node releases/v14.2/tests/native-routing.cjs <mihomo.exe>
node releases/v14.2/tests/native-dns-egress.cjs <mihomo.exe> <openssl.exe>
node releases/v14.2/tests/native-selectors.cjs <mihomo.exe>
python tools/verify-layout.py
python tools/package-v14.2.py --node node --fresh-routing --fresh-dns --core <mihomo.exe> --openssl <openssl.exe>
python tools/verify-layout.py --with-packages
```

最终交付目录为 `dist/v14.2/`；R2 修改及其审查元数据随两份 ZIP 交付。验证包独立复放不应访问公网、真实用户代理、订阅密码或运行中的客户端。**所有结果是已生成候选配置的测试，不表示已导入生产环境。**
