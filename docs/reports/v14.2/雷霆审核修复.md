## 五项整改

| 发现 | 修复后的行为 | 验证与边界 |
|---|---|---|
| P1-01：订阅存在时，组类型过滤同时删掉 DIRECT/REJECT | 类型过滤移到 provider 原始成员层，保留公共组 REJECT 和业务组 DIRECT；自定义表达式把节点改为直连/PASS 等时，结果被改为拒绝并从业务选择器隐藏 | 原生 file provider、原始节点、覆写表达式六种场景通过；保留用户已有过滤和表达式，重复执行不累积守卫 |
| P1-02：国内组丢失已选节点后自动 DIRECT | 国内组首项为 REJECT，初次默认用独立 `default-selected=DIRECT`；选择失效时拒绝，用户主动 DIRECT 则可用并跨重载保留 | 两脚本原始节点重载和 provider 更新实测通过；iOS 首项 REJECT、默认名称 DIRECT 的声明已生成，其原生缓存行为未验收 |
| P1-03：OpenAI Cloudflare 主机的连接与 DNS 分组不同 | `openai.com.cdn.cloudflare.net` 作为精确公司主机先于共享父域；未确认的子域继续进入公共基础服务，DNS 与之相同 | 两端真实 TCP/UDP 与 A/AAAA 出口验证；iOS 静态通过。未将整个 Cloudflare 命名空间交给 OpenAI |
| P1-04：iOS 远程公司域名命中公司组，DNS 却走兜底 | 生成器读取实际使用的固定提交本地分类器并校验哈希，补齐 DOMAIN/DOMAIN-SUFFIX 对应 Host DNS，按连接规则先后决定归属 | 原先 5,030 个远程域名 apex/child 错配样本消除；加上 CNAME 两例，iOS 本轮有限域名样本从 5,032 个错配降为 0。原生 Host/proxy 解释和连接复用未验收 |
| P2-01：Windows、Android/iOS 公司种子不同 | `data/rules/business-services.json` 统一维护原 Android 已有业务表并嵌入两个独立脚本；生成器继承同表 | `microsoftazure.com`、`byteoversea.com`、`ibytedtos.com` 及 recaptcha 子域等反例三端归组一致，TCP/UDP/DNS 回归通过 |

过滤顺序依照所测版本的 [provider 解析实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.31/adapter/provider/provider.go)，明确处理覆写发生在原始类型过滤之后的情况。丢失选择返回首项的行为对应 [Selector 实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.31/adapter/outboundgroup/selector.go)，生产生成的手动组字段在独立核心中直接验证。

## 保留的验收边界

DOMAIN/DOMAIN-SUFFIX 样本来自已审核表，比较每个 apex 和合成子域，并用独立索引核对连接规则优先级。这个有限集合不穷尽 DOMAIN-REGEX、DOMAIN-KEYWORD、USER-AGENT 的语言，也不证明动态公网租户全覆盖。iOS `dnsPolicy.nonFiniteMatchers` 记录这些边界；不能由有限域名零错配宣布全部 DNS 合同闭合。

三端仍有已记录的原生分类器、外部 DoH 防护、LAN 和 Azure 通配符边界差异。本轮共同业务种子已一致，但完整域名集合仍记录 356 个平台规则差异，未删除这些反证。iOS 异步 Azure 通配符无法等同 Mihomo 数字尾段正则；`miwifi.com` 的既有 LAN/UDP 差异保留。

Windows TUN、Android VpnService、Shadowrocket 原生 DNS/选择缓存、公网 IPv6、QUIC/Voice/WebRTC 的 VPN 外抓包均未在设备执行。API 的 Chrome/TUN 地址空间错误复测也未执行。操作步骤见 [使用说明](../../guides/使用说明.md)；本机 IPv6 回环通过不等于公网 IPv6 或手机接管通过。
