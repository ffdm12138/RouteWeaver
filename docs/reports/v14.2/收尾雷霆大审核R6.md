# V14.2 收尾雷霆大审核 R6

2026-10-11，当前修订 `thunder-closeout-r6`。按用户要求，再次对照[十一条最终需求](../../需求.md)审核 Windows FlClash、Android Mihomo 和 iOS Shadowrocket，并复验此前四项修复。需求正文、45 个固定远程来源及其原始/分类器字节未修改。**运行中的客户端未替换。**

本轮又发现并修复两项 P3 问题。当前源码合同、隔离本机核心和包完整性检查通过；本轮有限范围没有发现剩余可操作的源码缺陷。三端实机接管、Shadowrocket 原生运行、公网 IPv6 与 Chrome/TUN 仍待验收，不能宣称“全部实机需求已完成”或“没有任何 bug”。

## 本轮发现和修复

| 编号 | 反例与影响 | 修复和复验 |
|---|---|---|
| R6-01，P3 | Windows 移除旧 TUN 旁路字段后，第二次覆写丢失相应提醒；地址集合所依赖的未使用规则集也只在第一次输出中残留。完整输出不幂等，既有流量规则未变 | 在收集依赖之前移除本来就禁止的七种 TUN 字段，只保留当前版本、桌面标记中的七条精确提醒。仍被 sniffer 使用的规则集继续保留；七种单项及组合输入连续三次输出完全一致 |
| R6-02，P3 | Android 日志仍称“国内 TCP 双栈直连”，与可切换的「国内网站」组不一致 | 日志改为“国内 TCP 由国内网站组选择，默认 DIRECT”；控制台断言通过 |

默认 Windows/Android 配置除审核修订标记外与 R5 完全一致；Shadowrocket 配置原始字节与 R5 相同。R5 的 Epic/Disney 精确 CDN、通用 TCP STUN、Android IPv6 提醒和 DNS 观察标签四项修复重新通过，没有删除其范围说明。

有效修复前回执保留十条失败断言，归属于上述两个问题；第一次测试里缺失的合成规则集、独立索引的 iOS UDP 拒绝处理和已知单标签例外检查已在测试端纠正，不计作生产缺陷。沙箱首次拒绝回环控制器连接的 EACCES 失败也保留；取得隔离测试执行权限后完整复跑通过。

## 十一条逐项核对

| 需求 | 当前源码与本机验证 | 尚未完成的设备部分 |
|---|---|---|
| 1 公司归组、共享独立 | Google/Gemini/YouTube 同组；公司与共享域名对照、精确租户和 CDN 反例通过；10,636 个既有有限域名样本无分组差异 | Shadowrocket 原生匹配与真实业务流量 |
| 2 DNS 跟随组 | A/AAAA、切组、主动 DIRECT、DoH/DoT、坏节点拒绝共 818 项核心检查通过；业务样本 DNS 无错配 | 三端外侧抓包、系统/应用 DNS 与缓存 |
| 3 UDP 跟随与拒绝 | 业务 UDP、未知公网 UDP、无 UDP 节点相邻拒绝、QUIC/语音/STUN 样本通过 | Android/iOS VPN 和浏览器 WebRTC 实流量 |
| 4 双栈与防漏 | 核心双栈、IPv4/IPv6 地址规则、本机 IPv6 回环拨号通过 | 公网 IPv6、设备直连与代理、操作系统接管 |
| 5 主动 DIRECT 与失败边界 | 业务主动 DIRECT 保留；失效节点与协议不支持无自动直连 | 三端真实断节点观察 |
| 6 两个手动公共组 | 无 DIRECT、测速择优或故障切换候选；224 次选择、刷新、删除节点及重载观察通过 | 三端客户端实际存储与切换 |
| 7 统一兜底 | 未知 TCP/UDP/DNS 经漏网之鱼；明确 LAN/国内和手动例外保留；无 UDP 时拒绝 | 模式外流量与应用加密 DNS 的设备检查 |
| 8 业务与 STUN 优先级 | 公司先于地域；通用 TCP STUN 先于国内且不抢已知业务；INNER DNS 例外保留 | 未识别非标准加密流量不属于穷尽检查 |
| 9 安全更新 | 45 来源固定提交、90 份原始/分类器哈希一致；未审核 CDN/Azure 修改被写出前拒绝 | 未启用新远程候选，本轮无在线更新晋级 |
| 10 三端一致与分层验收 | 三端模型与 Windows/Android 配置的同一本机 Mihomo 核心通过；下述 52 个单标签例外明确保留 | iOS 原生、Windows TUN、Android VpnService 均 NOT_RUN |
| 11 国内集中切换 | 默认 DIRECT，可选两个公共组/单节点；公司/共享/LAN 优先级、未知 UDP/DNS 与 STUN 边界通过；全量国内表复审完成 | 三端实际切组、接管与失败行为 |

“源码通过”对应合同与有限反例；Windows/Android 核心结果来自本机 Windows Mihomo v1.19.31，不是 Android 实机通过。iOS 的规则/DNS结果来自源码模型，没有原生解析器执行证据。

## 全量国内表与已知差异

新增独立索引对全部 111,595 条已固定 CN 后缀检查根名称及一个子域，共 **223,190 个名称、2,008,710 次三端分流观察**，覆盖 TCP 443、UDP 49000 和不支持 UDP 的选择。744 次业务 DNS 归属检查无错配，未发现新增 UDP 错配。

保留 **52 个单标签名称差异**，例如 `cn`、`baidu`、`xn--fiqs8s`。它们没有点，Mihomo 的已审核 private 正则视为本地名称允许 DIRECT；iOS 在 R3 明确省略了这个未经原生验证的正则，其 TCP 走国内组、UDP 走漏网之鱼或拒绝。这是原有、已声明的边界，本轮没有把它改成“三端一致通过”，也没有添加未经验证的广泛 iOS 直连通配符。带点名称没有新增跨端差异。名称存在性或当前所有权不由本轮分流模型证明。

此前腾讯云无限数字规则仍只将 100 个复核精确名称归 Epic，其他同类名称三端统一公共基础服务；新编号需要审核。任意域名/IP、CNAME、应用自带加密 DNS、隐藏在普通 HTTPS 中的非标准 STUN 和整机零泄漏都没有穷尽验证。
